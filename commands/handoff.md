## 언제 쓰는가

tool call이 구조화된 `tool_use`로 직렬화되지 못하고 `<invoke>` / `<parameter>` /
`</invoke>` 같은 XML이 **응답 본문에 텍스트로 새어나오는** 실패(leak)가 발생했을
때, 같은 세션에서 재시도해도 복구되지 않는 경우가 있습니다. 이는 모델/하네스의
직렬화 실패이며, in-context few-shot self-poisoning으로 한 번 오염된 히스토리가
이후 호출을 계속 같은 깨진 포맷으로 복제합니다. (참고: anthropics/claude-code
#62344, #66400)

확인된 유일한 복구책은 **오염된 히스토리가 없는 새 세션**(`/clear` 또는 새 창)
입니다. 이 커맨드는 새 세션에 그대로 붙여넣어 작업을 이어갈 수 있는 **핸드오프
프롬프트를 채팅 본문 plain text로 생성**합니다.

수동 트리거 커맨드입니다. 사용자가 leak을 목격했을 때 `/handoff`로 직접
호출합니다.

## 핵심 출력 규칙 (반드시 준수)

- **이 커맨드의 최종 산출물(핸드오프 프롬프트)은 tool call 없이 순수 텍스트로만
  출력합니다.** leak 상황에서는 어떤 tool call도 다시 실패할 수 있으므로, 핸드오프
  본문을 만들 때는 tool을 호출하지 않습니다.
- 핸드오프 내용은 기본적으로 **현재 세션의 대화 맥락에서 그대로 정리**합니다. git
  로그나 브랜치 조회 같은 외부 조사는 leak과 무관하고 불필요한 tool call만 늘리므로
  하지 않습니다. 대화만으로 파악되지 않는 특정 파일의 현재 상태가 꼭 필요할 때만
  `Read`로 확인하되, 그 tool call마저 leak되면 즉시 멈추고 아는 내용으로 작성합니다.

## 절차

### 1. 작업 맥락 정리

이번 세션 대화에서 다음을 그대로 추려냅니다. 새로운 조사는 최소화합니다.

- 진행 중이던 **목표**(무엇을 하려던 작업인가).
- 지금까지 내려진 **결정 사항**(설계 선택, 사용자가 확정한 방향).
- **완료된 작업**과 **남은 작업**.
- 관련된 **정확한 파일 경로**와 다음 실행할 **명령**.

### 2. 핸드오프 프롬프트 작성 (plain text, tool call 금지)

아래 형식으로 **채팅 본문에 그대로** 출력합니다. 사용자가 복사해 새 세션 첫
메시지로 붙여넣을 수 있어야 합니다.

```
## 세션 인계 (tool-call leak으로 세션 전환)

### 목표
<진행 중이던 작업의 목표 1-2줄>

### 확정된 결정
- <결정 1>
- <결정 2>

### 완료된 작업
- <완료 항목 + 관련 파일 경로>

### 남은 작업
1. <다음 단계> — 파일: `<경로>`
2. <다음 단계> — 명령: `<명령>`

### 참고
- <주의점, 의존성, leak이 발생한 지점 등>
```

### 3. 마무리 안내

핸드오프 프롬프트 출력 직후, 마지막 줄에 한 줄로 안내합니다:

> 위 내용을 복사해 새 세션(`/clear` 후 또는 새 창)에 붙여넣어 작업을 이어가세요.

## Rules

- 모든 사용자 대면 출력은 한국어로 작성합니다.
- 핸드오프 프롬프트 본문에는 **tool call을 절대 포함하지 않습니다.**
- 추측으로 빈칸을 채우지 말고, 불확실한 항목은 `(불확실)`로 표시합니다.
- 핸드오프는 간결하게. 새 세션이 바로 행동할 수 있는 정보만 담고, 과정 서술은
  생략합니다.
